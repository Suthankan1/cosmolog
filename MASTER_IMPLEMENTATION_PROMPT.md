## Technical constraints
- Expo/React Native/TypeScript with the actual installed SDK and native project; Redux Toolkit thunks per ADR-008, SQLite repositories with serialized writes, SecureStore verified account, NetInfo, existing adapters and file ownership policy. Do not migrate to RTK Query merely because older starter documents mentioned it.
- No custom backend, remote AI or third-party credentials for planned local-first features. No broad dependency updates. Install native modules only when needed, with compatible Expo version and actual native checks.
- Preserve first sign-in online, returning verified offline session, sign-out invalidation, source-specific committed sync timestamps, all saved ownership, private notes and durable permitted media. New migrations are additive and forward-only; tests against existing populated DB and rollback required.
- All private reads and writes scoped by verified account. Cancel stale work on sign-out, minimize permissions, no background GPS/mic/sensor loops, no secrets or private data in logs. Local privacy is not database encryption. Separate user-owned photos from licensed source media. Keep validated files safe through shared ownership, crash reconciliation and explicit deletion.
- Science data must have source URL, units, precision, edition/revision, credit and rights; reject NaN/infinite and invented claims. Use original prose and permitted images, distinguish observation/inference/illustration and dated forecasts. Do not create fake cultural data, calendar dates or image licenses. No unconditional offline voice promise.
- Magazine visual language: outlined masthead, cut C, Playfair Display and Inter, warm ivory/forest, brass, terracotta/sage, ruled sections, Feather icons, real attribution. Use responsive layout, minimum targets, readable contrast, screen-reader labels, safe areas and reduced motion. Night mode is opt-in dark red treatment only, not the default aesthetic. No unsupported interactive controls.
- Preserve assignment core, existing bonus selection, genuine evidence and the deadline freeze.

## Execution protocol
1. Identify the first incomplete acceptance criterion in the earliest open release task. First run a baseline regression check and inspect related tests. Report exact evidence and blockers; do not claim historical results as new runs.
2. Create a small branch from main (e.g. feat/expedition-progress). Draft a concise plan with affected files and tests, then implement that slice, not a broad rewrite. Prefer pure logic or migration/repository tests first, then UI integration. Keep data contracts and route params typed.
3. Run targeted tests then npm run lint, npm run typecheck, npm test -- --runInBand. For native/config/UI changes, run relevant device/build checks and capture real screenshots. Preserve the existing test suites; don't weaken assertions to obtain green.
4. Check offline cold start without Metro, reconnect, account isolation and permission/error paths relevant to the feature. Confirm source/rights and accessibility. Update docs/PROGRESS.md, relevant ADR and task checkboxes with actual evidence. Record actual AI use and corrections in AI_USAGE.md; do not invent student decisions.
5. Commit the focused change and open a PR to main with summary, release/feature ID, tests, data migration/rollback implications and screenshots. Do not self-merge, tag, publish a release or bump versions before the full release gate. If blocked, report exact missing prerequisite, keep prior code safe, and don't fake completion.
