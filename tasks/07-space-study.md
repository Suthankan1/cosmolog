# Space Study implementation plan

Proposed 23 November 2026 for IN3210. The assignment deadline is 13 December 2026 at 23:59 local course time. Dates and scope below are planning targets. No new runtime dependencies or services are assumed.

## What a learner should be able to do

From Discover, open Space Study, search for “Saturn”, read a chapter on planetary systems, follow a link to Titan, save it to the Field Shelf, and resume the same section after restarting in airplane mode. From either the book or the existing Sky Viewer, choose Kandy by name or tap Use my location, see which supported objects are above the local horizon, and open their study entries. Searching “Starlink” should explain the constellation first and offer individually identified spacecraft where an installed catalog provides them.

A **complete book** means one specified edition with every chapter available inside the reader. A **catalog** has an identified source, release, selection rule and record count. The universe has no complete inventory. Publish a coverage screen showing which families have lessons, which catalogs are installed, their limits and dates, and which entries support sky positions. A learner should be able to read about Earth, a retired rocket or a distant exoplanet even when there is no meaningful local pointing target.

## Starting point

Discover, Field Shelf, account-owned notes, local search, reading progress, durable media and APOD reading packs already exist. Those packs contain dated discovery records. Book chapters need stable sections, a reading order and edition metadata. Sky Viewer already has a Colombo preview, coordinate input, optional foreground GPS, manual pointing, accessible list and detail sheet. Bundled data covers 80 named stars, six Messier objects, the Moon and seven planets. Current working-tree changes implement validated orbital elements and local predictions for ISS and Hubble. Reconcile that work before adding a migration. Device verification recorded in docs/PROGRESS.md includes Android emulator runs. Physical pointing and native iOS still need verification.

- For a full astronomy text, evaluate a versioned, locally formatted edition of OpenStax *Astronomy 2e*. Its current preface specifies noncommercial share-alike terms and per-page attribution. Review each figure credit and distribution terms for the intended release, preserve required notices, equations, tables and accessible figure descriptions, and process the book using a deterministic importer. Count every chapter and section against that edition’s contents. If reuse is unavailable, ship original reviewed chapters under a distinct COSMOLOG edition and identify remaining coverage. Spaceflight and Starlink need original supplemental chapters either way. [OpenStax preface and reuse terms](https://openstax.org/books/astronomy-2e/pages/preface)
- Use original, cited summaries for vehicle histories and satellite families. Separate the source of a fact from permission to redistribute a photo. Link launch records and mission pages to their named objects. Preserve release information, credits, links, units and uncertainties. Mark unknown values explicitly. Start with [NASA missions](https://science.nasa.gov/mission/) and the [NASA exoplanet catalog](https://science.nasa.gov/exoplanets/exoplanet-catalog/).
- Import selected small bodies by stable identifiers. JPL SBDB supplies orbital and physical fields for asteroids and comets. Chart support requires a separately validated ephemeris calculation. [JPL SBDB](https://ssd-api.jpl.nasa.gov/doc/sbdb.html)
- Use the existing catalog attribution records in src/features/sky/catalog/README.md. Use an attributed GeoNames city extract with country, region, alternate names, coordinates and time zone. Publish its inclusion rule, initially Sri Lankan towns and a bounded world-city set, with optional country packs. [GeoNames downloads and terms](https://www.geonames.org/export/)
- Use CelesTrak GP JSON and its documented group query for a larger Starlink pack. Accept catalog numbers beyond five digits. Check distribution terms before publishing third-party snapshots. [GP formats](https://celestrak.org/NORAD/documentation/gp-data-formats.php) · [Usage policy](https://celestrak.org/usage-policy.php)

## Screens and data flow

1. Keep Discover, Favourites and Profile. Add a protected Space Study entry on Discover with Continue reading, chapters, object search, downloads and Open sky. Use the v2 editorial tokens, Feather, scalable text and 48 dp controls. Extend the existing Sky Viewer in place.
2. The reader has a table of contents, previous/next section, glossary links, figure captions, sources and bookmarks. Link chapters to object profiles and profiles back to the relevant section. Use typed source and ID route params. Resolve them from SQLite. Add “Read in Space Study” to supported chart details.
3. Search installed text, titles, aliases and identifiers. Rank exact catalog IDs and names first, then aliases, chapter headings and body matches. Group results by chapter, object and existing discovery content. Match cases such as “M31”, “Andromeda Galaxy”, “ISS” and “25544”. Show downloadable collections separately when coverage is missing. Use paginated parameterized queries, escaped search input and an indexed alias table. Benchmark before enabling SQLite full-text search and verify capability on both native builds.
4. City search runs locally. Disambiguate duplicate names with region and country. Preserve a manually chosen city across restarts and allow clearing it. Offer manual coordinates when a city is missing. Keep precise device fixes in memory, request only foreground permission on demand and show the fix source, age and accuracy. Compute the sky on-device for the observer coordinates and instant. Display local time for the observing city.
5. For each chartable object show direction, elevation, calculation time and horizon status. A positive elevation is geometric. Daylight, satellite illumination, weather and equipment affect actual visibility. Retain manual controls and the accessible list when permission, sensors or GPS are unavailable. A later “Tonight” view can add rise/set and predicted satellite passes after numerical validation, including polar-day and no-pass cases.

## Storage, updates and failure recovery

Extend the current SQLite migration chain with edition, chapter, section, study object, alias, chapter–object link, city, pack revision and membership tables. Use stable namespaced object IDs, edition-specific section anchors and foreign keys. Keep the existing discovery-source union for news/APOD. Add study-specific typed routes and account-owned bookmarks/progress, then compose both repositories in the Shelf. A Starlink spacecraft belongs to a constellation through a relationship. Store time-varying elements separately under its NORAD ID. Use the existing Redux Toolkit thunk lifecycle per ADR-008 for downloads, cancellation and reconnect. SQLite serves every reader and search screen.

| Data | Proposed refresh policy | Offline contract |
| --- | --- | --- |
| Starter lessons, glossary, atlas, cities | Seed once per bundled revision. Check a lightweight content manifest at most daily while online and foregrounded. | Available immediately inside an authenticated session. First login still needs connectivity. Label the bundled edition by version. |
| Full book, expanded catalogs, country and media packs | Offer size and version before download. Default large downloads to explicit action. Offer opt-in updates on Wi-Fi. Fetch changed packs only, initially at release or through a versioned static asset host. | Installed chapters, diagrams and captions open from SQLite and persistent files. List coverage, byte size and update availability in Downloads. |
| Saved content and reading position | Write a save immediately. Checkpoint progress on section changes and on leaving the reader. Preserve stable anchors through edition updates or reopen the nearest retained heading. | Account-owned favourites, required files and notes survive eviction of an unrelated pack, logout/login to the same account, and process death. |
| Satellite elements | While the relevant viewer or pack is in use and online, fetch the needed query at most once per provider update, currently two hours. Deduplicate overlapping requests and respect host policy. Stop on non-200 and surface the provider problem for review. | Recompute from cached elements and UTC time locally. Use the current epoch-age policy, flag from 24 hours and suppress at 72 hours. Always show the study entry. |
| Sky direction | Recalculate on time or observer changes while the viewer is open. Limit calculations to selected or shortlisted targets. | No network writes per chart frame. Sleep the viewer off-screen. |

Use a versioned manifest with expected counts, minimum schema version, byte sizes, checksums and source metadata. Stage downloads, validate schemas and identifiers, verify bytes, then activate a complete revision transactionally. Readers continue using the previous revision during an update. Resume verified chunks after interruption. Garbage-collect abandoned files and unreferenced revisions after activation. Check disk space before starting. Explicit pack removal preserves bookmarked sections, required media and dependencies. Keep the bundled starter recoverable. Record attempt, successful commit, provider epoch and content edition separately. Handle unknown connectivity, no matches, missing pack, invalid update, unavailable source and old orbit data with distinct messages. On reconnection, run only work that is due. The plan requires neither a continuously running background service nor an application backend.

## Delivery sequence and acceptance gates

Targets assume one student, a working baseline and short reviewed commits. Complete each gate before starting the next slice. Where the deadline conflicts with an expansion, release a smaller accurately labelled edition.

| Target | Feature commit | Gate |
| --- | --- | --- |

Record the edition, license, source links, family coverage and download budget. Explain any schema/dependency decision in docs/DECISIONS.md before implementing it. |
| Nov 26–28 | One offline chapter end to end | Bundle one Saturn chapter, Saturn and Titan profiles, native routes and attribution. Prove seeded content renders in airplane mode after session restoration. Migrate an existing database with favourites intact. |
| Nov 29–Dec 1 | Search, bookmarks and resume | Add aliases, chapter search and Field Shelf integration. Confirm exact-ID ranking, ownership across two accounts, save/reopen after process death, readable large text and screen-reader navigation. |

Simulate low disk, corrupt download, app termination and reconnect while an old edition is open. A full-book label requires the complete contents check. |

Before accepting a large catalog, measure installed bytes, peak import memory, cold-open time, search latency and chart interaction on the target Android device. Initial targets are a starter pack under 10 MB compressed and first-page local search within 300 ms at the 95th percentile on a representative installed catalog. Adjust from device evidence. Test numerical sky fixtures against independent reference positions with recorded time, location, units and tolerances. Re-run the assignment’s original feed, auth and favourites acceptance flow after every migration. If the full edition misses the freeze, publish the measured starter edition, finish the submission evidence, and carry the complete book forward as the next milestone.
