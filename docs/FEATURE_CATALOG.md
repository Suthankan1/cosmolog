# Feature catalogue — twelve approved expansions

All entries are planned increments on the inspected v1.1.1 baseline. Each must work in the protected account shell, keep the editorial magazine identity, disclose data freshness and source rights, and have an accessible non-gesture path. Use existing repositories and modules where possible. Effort below is a rough estimate in focused engineering days, not calendar promises or marks.

## F01 — Expedition Packs (v1.2.0; 2–4 days)
**Value:** a guided, themed, offline science expedition rather than a pile of downloaded articles. Start by evolving existing Saturn/Apollo packs, adding ordered reading, study sections, observation prompts, completion and source context. A Moon or Saturn pack should link a real existing object/lesson and an optional observation.
**Entry:** Discover's Study, sky and archives → Expedition Packs; Field Shelf tools → downloaded expeditions. Pack detail: cover, curator intro, source/rights, estimated and installed bytes, ordered checklist, text/image/lesson readiness, progress, retry/cancel/resume/removal. Show distinct partial, text-only, ready and update-available states.
**Reuse:** app/reading-packs.tsx, src/features/discovery/readingPacks.ts, readingPacksRepository, src/features/study/packDownloads.ts and packRepository, existing mediaPolicy and image worker. Keep article pack ownership and global study edition installation separate. A pack may reference either; do not duplicate content. No backend.
**Acceptance:** download interrupted mid-entry, app terminated, airplane-mode restart renders completed items; resume skips validated entries. Offline prompts/reading progress survive restart and account switching. Removing an expedition never deletes a favourite, note, other expedition or study bookmark; unknown image rights are text-only. Manifest revision mismatch, bad hash, insufficient storage and missing media have tests. No need for a full new remote pack server.

## F02 — Offline Library Manager (v1.2.0; 1–3 days)
**Value:** show the user what is actually available offline and why a file is retained.
**Entry:** Profile storage and Field Shelf tools → Offline Library; separate content, image files, expeditions and study supplements. Show installed physical bytes once per file, account-owned items, shared-file status, eligible-to-remove cache, text-only reason, pending/failure state. Retry only eligible items when online. Preview removal impact; confirm destructive actions.
**Reuse:** src/database/repositories/mediaRepository.ts, readingPacksRepository, discoveryRepository, study/packRepository.ts, src/services/storage/imageStorage.ts, Profile and archive lifecycle. Use existing offline_item_owners view; add a read projection first, not a parallel cache.
**Acceptance:** multi-account/shared-file ownership, missing-file reconciliation, text-only and previous-revision labels, repeated clear, partial failures; deleting a cache never removes active feed membership or user-owned content; counts reflect actual verified files; show shared storage without revealing other accounts' private data. Do not claim database page size equals reclaimable storage.

## F03 — LightTrace (v1.3.0; 1–3 days)
**Value:** reveal the approximate age of arriving light from familiar objects. Select Moon, Sun, nearby star, Andromeda; move through a logarithmic distance ruler; show travel duration, reference frame and source. Link to Study/Sky Viewer object where valid.
**Entry:** Discover → Explore / LightTrace; object detail → LightTrace for supported distance.
**Data:** exact c = 299792458 m/s (BIPM); AU definition; NASA solar system and cosmic distances; existing HYG stars when licensed and distance not null. Store distance value/unit, kind, reference/epoch, precision and citations. Use d/c only for local/nearby approximations; do not treat cosmological comoving distance divided by c as lookback time. No precise ancient timestamp for uncertain distances. See source registry.
**Architecture:** pure units/math module in src/features/labs; bundled versioned reference dataset; React Native accessible controls and optional SVG if justified. No network or permissions.
**Acceptance:** Moon order ~1.3 seconds, mean Sun ~8.3 minutes, Proxima ~4.24 years, M31 ~2.5 million years as rounded examples; invalid, null, negative and nonfinite values rejected. Unit conversions and log endpoints tested. Accessible numeric/text equivalent to visualization; works airplane mode.

## F04 — Cosmic Scale Laboratory (v1.3.0; 2–3 days)
**Value:** compare body diameters, distance and hypothetical constant-speed travel. Separate diameter and distance scales; same denominator for compared bodies; label schematic if not to scale. Let user choose objects and speed preset/custom input; display units and assumptions.
**Data:** NASA planet sizes and mean orbital distances; reuse F03 unit contracts. Select consistent diameter convention (e.g. equatorial) and distinguish mean orbital distance from instantaneous Earth distance. Travel time = distance/speed for constant speed ignoring acceleration, trajectories and relativistic effects. Do not imply feasible spacecraft journey.
**Acceptance:** reject zero/negative/nonfinite speed, physical travel speeds >= c, same-object and missing data cases; no false precision. Compare ratios with golden tests, numeric fallback, large-text interaction and no network dependency. Link relevant study entries. No duplicate astronomical computation library.

## F05 — Advanced Field Notes (v1.4.0; 3–5 days)
**Value:** independent personal observation entries, not just annotations attached to saved articles. Capture title, observed time/time zone, target (optional typed SkyObjectId), notes, qualitative sky conditions, optional city/coordinates and optional photo; attach related discovery or study entry. Quick capture offline, edit/delete, compare/filter later. Existing article/study notes remain as annotations, not automatically reclassified as observations.
**Entry:** Fieldwork hub / Field Shelf tools → Observations list → new/edit/view; Sky Viewer → Record observation prefilled from selected object only on consent.
**Architecture:** new account-scoped observation repository and additive SQLite migration, relative app-private file references, separate image ownership from licensed source media. Reuse FieldNote editor patterns and useVoiceToText hook; typed local IDs and explicit foreground permission. Optional photo phase uses expo-image-picker only after SDK/native compatibility check; remove unnecessary permissions, size limit, normalize file type, strip location metadata where feasible; if stripping not supported, warn/omit import or clearly retain local only. No automatic upload or public visibility.
**Acceptance:** text creation/edit/delete without network, account isolation, invalid coordinates, timezone round-trip, interrupted file write, missing file, denied permission, app restart, stale async completion after logout. Deleting observation never deletes source bookmark. Do not claim sync across devices.

## F06 — Celestial Field Instrument (v1.4.0; 1–3 days)
**Value:** readable heading and inclination instrument for field measurements with a one-tap snapshot attached to F05. Show magnetic vs true heading explicitly, accuracy/availability and last sample time. An observational aid, not safety navigation or guaranteed celestial identification.
**Reuse:** src/features/sky/useSkyPointing.ts, pointing.ts, projection.ts, skyMath.ts, SkyViewer. Derive orientation from existing validated vectors; expose raw/derived readings through a shared hook rather than mounting concurrent watchers. Reuse Astronomy Engine for supported target geometry. Sensor data transient unless the user confirms capture.
**Acceptance:** north/east/wrap/tilt fixtures, true-vs-magnetic labels, no declination/no location fallback, interference or unavailable hardware, stale samples, screen blur/background/logout cleanup, manual direction and accessible text alternative. Never hardcode Polaris as magnetic north or promise it is visible everywhere. Never use phone pointing to guide a user to stare at the Sun; prominent solar safety text for Sun targets. No background location/sensing.

## F07 — Behind the Discovery (v1.5.0; 2–4 days)
**Value:** evidence dossiers explain observation → instrument/method → inference → uncertainty, distinguishing observation, model and illustration. Begin with 2–3 curated, versioned cases (e.g. Webb WASP-39 b spectroscopy). Include an explicit "what this does not prove" and dated source links. Tie dossiers to existing study entries or discoveries with stable IDs.
**Reuse:** Space Study reader, study repository and validated content pack pattern; add typed evidence blocks, not a generated AI summary of arbitrary news. Source registry includes NASA primary material. Use original prose or licensed assets; label artist concepts and graphs.
**Acceptance:** all four evidence sections, at least one specific authoritative source per claim, verified attribution, unknown claim handling, offline reader and source link gracefully unavailable. Independent content review required; no unsourced scientific claims or false certainty. No new AI service.

## F08 — One Sky, Many Stories (v1.5.0; 3–5 days)
**Value:** compare documented cultural sky traditions on the same star positions. Begin with one small region (e.g. Orion-area stars) and two responsibly researched traditions. Names, line segments, translation and cultural/historical notes are sourced and individually credited. No assumption that all people in a culture share one sky story.
**Reuse:** bundled HYG star identities, projection and SkyChart; add a curated adapter for stable Hipparcos IDs or an explicitly licensed additional subset. Toggle layers side by side or overlay; static local diagrams and text list work without sensors/location. Preserve same projection, epoch and zoom so comparison is meaningful.
**Acceptance:** verified IDs/endpoints and missing-star handling, overlay alignment and labels, appropriate author/license/version per text/line/illustration, accessible list and offline restart. If no redistribution rights or reliable source, do not bundle the tradition yet. Never generate pseudo-cultural lore. Do not import the whole Stellarium catalog indiscriminately.

## F09 — Personal Sky Timeline (v1.6.0; 1–3 days)
**Value:** a personal history of saved discoveries, completed readings, independent observations and optionally bookmarked study entries/events. Filter by kind and date; jump back to the underlying record. Clearly distinguish publication, save, read, and observed dates.
**Reuse:** favourites.added_at, reading_history.read_at, observations.observed_at and study bookmarks (only if a trustworthy timestamp exists; otherwise omit or label undated). Derive a read model rather than append duplicate events for every operation. Account-filter at query boundary; indexed stable cursor (timestamp, kind, stable ID), grouped local dates.
**Acceptance:** chronological deterministic ties, timezone/day-boundary, account isolation, source deletion/edit, no invented timestamps, pagination, empty state, offline cold start. Timeline is not activity analytics or a social feed.

## F10 — Meteor Calendar (v1.6.0; 1–3 days)
**Value:** plan observations with verified annual active windows and peak estimates. Show calendar year, UTC and selected city local time where exact UTC is known, radiant and moon conditions only from checked data/calculations, and useful observing guidance. Link an observation entry and optionally a relevant Sky Viewer target.
**Data:** International Meteor Organization calendar, American Meteor Society cross-check; review annual edition, cite year/source, clarify estimates and ZHR is an idealized rate (not a local forecast). If time is a date only preserve date precision; do not invent midnight or specific peak hour. No weather forecasts without a source. Use existing city timezone and Astronomy Engine if useful. No notifications required; optional explicit local reminder in a separate tested slice.
**Acceptance:** current and future year metadata, offline calendar, UTC/local formatting incl. half-hour offsets, unknown peak times, expired dataset warning and source corrections, no visibility guarantee; no silent annual date reuse. Don't copy proprietary calendar wholesale without permission.

## F11 — Read Aloud (v1.7.0; 1–2 days)
**Value:** listen to cached APOD explanations, publisher summaries and Study sections; play/stop, speech rate, clear progress/section indicator. Speech synthesis is distinct from already implemented voice recognition.
**Entry:** reading header/toolbar; accessible speaker action. Use expo-speech only if compatible with installed Expo SDK; OS voices/languages vary; detect available voice and test offline; no assertion that all voices work offline. iOS silent mode caveat; gracefully explain unavailable audio. No microphone permission for TTS.
**Acceptance:** chunk long text within platform maximum, no overlapping reading or recording, stop on back/blur/logout, interruption/error handling, voice unavailable/no network and silent mode; do not claim full news articles beyond publisher summaries. Add mocked lifecycle tests and real device checks.

## F12 — Night Observation Mode (v1.7.0; 2–4 days)
**Value:** optional dark, dim red-on-charcoal field-reading theme, not the default brand. Accessible text/controls and clear way out, preserve choice across restart (account setting); brightness only as an explicit user-controlled stretch feature, restore if changed. Dark adaptation depends on intensity/duration and environment; do not promise preservation.
**Entry:** Profile reading preferences and Fieldwork quick control. Add semantic theme provider/token roles, migrate screens progressively but ship only after consistent end-to-end coverage including status bar, modals, tabs, charts and error states. Do not replace magazine palette for default. Ensure strong contrast, no state conveyed by red alone, no forced system brightness.
**Acceptance:** persists across restart and account changes according to stated policy; color contrast, font scale, focus order, reduced motion, foreground lifecycle, unavailable media and first-launch states. Native system UI may not obey app palette; explain rather than fake. Keep existing selected Reanimated bonus as the assignment's one bonus claim.

## Cross-feature journeys
- Discover a Saturn article → open linked expedition → download and restart offline → compare Saturn/Earth scale → see a related evidence dossier → log an observation with optional instrument snapshot → revisit the timeline.
- Compare a documented star tradition → inspect the same stars in Sky Viewer → plan a meteor observation → note the conditions → revisit from Field Shelf.
- Read any supported cached item aloud in Night Observation Mode without requiring extra network calls.
